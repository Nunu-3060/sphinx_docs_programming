pdb

Python に標準で組み込まれている、対話的なソースコードデバッガ。プログラムの実行を任意の場所で一時停止し、その時点の変数の値を確認したり、1 行ずつ実行しながら処理の流れを追ったりできる。print を挿入してのデバッグでは追いきれない複雑な不具合の調査に役立つ。

デバッグセッションの開始

スクリプト全体を最初から pdb の管理下で実行したい場合は、python -m pdb を使ってスクリプトを起動する。プログラムの先頭で自動的に一時停止した状態から始まる。

1$ python -m pdb myscript.py

コードの特定の場所でだけ一時停止したい場合は、その位置に組み込み関数 breakpoint() を呼び出すコードを挿入する。これが標準的な方法で、デフォルトでは内部的に pdb.set_trace() を呼び出す（sys.breakpointhook や環境変数 PYTHONBREAKPOINT を設定することで、別のデバッガを呼び出すように変更することもできる）。

1def calculate(a, b):
2    breakpoint()  # ここで実行が一時停止し、pdb のプロンプトが起動する
3    return a / b
4
5calculate(10, 0)

pdb セッション内でのコマンド

breakpoint() や python -m pdb によって (Pdb) プロンプトが表示された状態になったら、以下のようなコマンドを入力して対話的にデバッグを進める。これらは実行可能な Python コードではなく、pdb のプロンプトに直接入力する対話コマンドである点に注意する。

  • n (next) --- 現在の行を実行し、次の行へ進む（関数呼び出しの中へは入らない）。

  • s (step) --- 現在の行を実行し、関数呼び出しがあればその内部へステップインする。

  • c (continue) --- 次のブレークポイント（または breakpoint() の呼び出し）まで実行を再開する。

  • l (list) --- 現在実行中の行の周辺のソースコードを表示する。

  • p <式> (print) --- 指定した式を評価し、その結果を表示する（例: p a、p a + b）。

  • q (quit) --- デバッグセッションを終了し、プログラムの実行を中断する。

pdb.pm

プログラムが例外を送出して異常終了した「後」に、その時点のトレースバックに対してデバッガを起動する（ポストモーテムデバッグ）。対話的な REPL でコードを実行していて、事前に breakpoint() を仕込んでいなかった場合に、発生した例外の状況をさかのぼって調べたいときに使う。

 1>>> def divide(a, b):
 2...     return a / b
 3...
 4>>> divide(10, 0)
 5Traceback (most recent call last):
 6  File "<python-input-1>", line 1, in <module>
 7    divide(10, 0)
 8    ~~~~~~^^^^^^^
 9  File "<python-input-0>", line 2, in divide
10    return a / b
11           ~~^~~
12ZeroDivisionError: division by zero
13>>> import pdb
14>>> pdb.pm()
15> <python-input-0>(2)divide()
16(Pdb) p a
1710
18(Pdb) p b
190
20(Pdb) q

<python-input-N> は Python 3.13 以降の対話モード（REPL）で入力した各コードに付けられる名前である。

注釈

VS Code や PyCharm などのエディタ・IDE が備えるグラフィカルなデバッガも、基本的には pdb と同じ仕組み（ブレークポイント、ステップ実行、変数の検査）の上に構築されている。とはいえ pdb は追加のインストールや設定が不要で、SSH 接続先のサーバーなど IDE を使えないターミナル環境で手早くデバッグしたい場合に今でも有用である。

Python 3.13 / 3.14 での主な改良

近年のバージョンでは pdb 自体の使い勝手も向上している。

  • Python 3.13 では exceptions コマンドが追加され、ポストモーテムデバッグの際に、連鎖した例外（__cause__/__context__）を切り替えて調べられるようになった。

  • Python 3.14 では、表示されるソースコードがシンタックスハイライトされるようになったほか、python -m pdb -p <PID> で実行中の別の Python プロセスにデバッガをアタッチできるようになった（リモートアタッチ）。

1$ python -m pdb -p 12345
