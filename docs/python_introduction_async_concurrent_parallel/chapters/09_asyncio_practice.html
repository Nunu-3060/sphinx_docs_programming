第 9 章 asyncio による非同期処理（実践）

この章では、asyncio を実際のプログラムで使うときに必要になる技術を説明する。同時実行数の制限、キューによる仕事の分配、ブロッキングする処理との組み合わせ、キャンセルと後始末、ネットワーク通信を扱う。

同時実行数の制限

asyncio では、タスクを作るだけで数千の処理を同時に開始できる。しかし、接続先のサーバーに数千の要求を一度に送ると、相手に過大な負荷をかけたり、接続を拒否されたりする。開けるファイルやソケットの数にも OS の上限がある。そのため、実際のプログラムでは同時に実行する数を制限する必要がある。

同時実行数の制限には asyncio.Semaphore を使う。Semaphore(4) は、async with ブロックに同時に入れるタスクを 4 つまでに制限する。5 つ目のタスクは、どれかのタスクがブロックを抜けるまで待たされる。

次のサンプルでは、asyncio のストリームを使ってローカルに TCP のエコーサーバーを起動し、12 個のクライアントから接続する。同時に接続するクライアントは Semaphore で 4 つまでに制限する。

echo_semaphore.py

 7import asyncio
 8import time
 9
10HOST = "127.0.0.1"
11CLIENTS = 12
12LIMIT = 4
13
14
15class Stats:
16    """サーバーが同時に処理している接続数を記録する。"""
17
18    def __init__(self) -> None:
19        self.current = 0
20        self.peak = 0
21
22
23async def handle(reader: asyncio.StreamReader, writer: asyncio.StreamWriter, stats: Stats) -> None:
24    """受け取った 1 行を 0.5 秒後にそのまま送り返す。"""
25    stats.current += 1
26    stats.peak = max(stats.peak, stats.current)
27    try:
28        line = await reader.readline()
29        await asyncio.sleep(0.5)  # 時間のかかる処理の代わり
30        writer.write(line)
31        await writer.drain()
32    finally:
33        stats.current -= 1
34        writer.close()
35        await writer.wait_closed()
36
37
38async def client(number: int, port: int, semaphore: asyncio.Semaphore) -> str:
39    async with semaphore:  # 同時に LIMIT 個を超えて接続しない
40        reader, writer = await asyncio.open_connection(HOST, port)
41        try:
42            writer.write(f"こんにちは {number}\n".encode())
43            await writer.drain()
44            reply = await reader.readline()
45        finally:
46            writer.close()
47            await writer.wait_closed()
48    return reply.decode().rstrip()
49
50
51async def main() -> None:
52    stats = Stats()
53
54    async def on_connect(reader: asyncio.StreamReader, writer: asyncio.StreamWriter) -> None:
55        await handle(reader, writer, stats)
56
57    server = await asyncio.start_server(on_connect, HOST, 0)  # ポート 0 で空いているポートを使う
58    port = server.sockets[0].getsockname()[1]
59    async with server:
60        semaphore = asyncio.Semaphore(LIMIT)
61        start = time.perf_counter()
62        async with asyncio.TaskGroup() as group:
63            tasks = [group.create_task(client(i, port, semaphore)) for i in range(CLIENTS)]
64        elapsed = time.perf_counter() - start
65
66    for task in tasks:
67        print(task.result())
68    print(f"同時接続数の最大: {stats.peak}, 経過時間: {elapsed:.1f} 秒")
69
70
71if __name__ == "__main__":
72    asyncio.run(main())

実行すると、次のような結果になる。

こんにちは 0
こんにちは 1
（中略）
こんにちは 11
同時接続数の最大: 4, 経過時間: 1.6 秒

サーバーは 1 件の要求に 0.5 秒かけて応答する。12 件を 4 件ずつ処理するため、全体は約 1.5 秒になる。同時接続数の最大が 4 になっていることから、Semaphore による制限が効いていることが分かる。

このサンプルで使っているストリームの API は次のとおりである。

表 17 asyncio のストリームの主な API

API

説明

asyncio.start_server(handler, host, port)

TCP サーバーを起動する。接続があるたびに、handler(reader, writer) が新しいタスクとして実行される。

asyncio.open_connection(host, port)

TCP サーバーに接続し、StreamReader と StreamWriter の組を返す。

await reader.readline()、await reader.read()

データを受信する。データが届くまでの間、他のタスクが実行される。

writer.write(data) と await writer.drain()

データを送信する。write() は送信用のバッファにデータを入れるだけなので、drain() でバッファに空きができるまで待つ。

writer.close() と await writer.wait_closed()

接続を閉じ、閉じ終わるまで待つ。

実務で HTTP の通信を行う場合は、aiohttp や httpx などの非同期に対応した HTTP クライアントのライブラリを使うのが一般的である。標準ライブラリの urllib.request は同期的な API なので、asyncio から使う場合は後で説明する asyncio.to_thread() を使う。

キューによる仕事の分配

asyncio.Queue は、asyncio のタスク間でデータを受け渡すためのキューである。queue.Queue と同じように使えるが、get() や put() は await で待つコルーチンになっている。決まった数のワーカータスクに仕事を分配する場合に使う。

worker_queue.py

 6import asyncio
 7import random
 8
 9
10async def worker(name: str, jobs: "asyncio.Queue[int]", results: list[str]) -> None:
11    while True:
12        number = await jobs.get()
13        try:
14            await asyncio.sleep(random.uniform(0.1, 0.5))  # I/O 処理の代わり
15            results.append(f"{name} が仕事 {number} を処理した")
16        finally:
17            jobs.task_done()  # 処理が終わったことをキューに知らせる
18
19
20async def main() -> None:
21    jobs: "asyncio.Queue[int]" = asyncio.Queue()
22    for number in range(10):
23        jobs.put_nowait(number)
24
25    results: list[str] = []
26    workers = [asyncio.create_task(worker(f"ワーカー {i}", jobs, results)) for i in range(3)]
27
28    await jobs.join()  # すべての仕事で task_done() が呼ばれるまで待つ
29
30    for task in workers:
31        task.cancel()  # 無限ループで待ち続けているワーカーを終了させる
32    await asyncio.gather(*workers, return_exceptions=True)
33
34    print("\n".join(results))
35
36
37if __name__ == "__main__":
38    asyncio.run(main())

このサンプルのポイントは次のとおりである。

  • ワーカーは while True のループで仕事を取り出し続ける。仕事を 1 つ処理し終えるたびに task_done() を呼ぶ。

  • jobs.join() は、キューに入れたすべての仕事で task_done() が呼ばれるまで待つ。

  • すべての仕事が終わった後、ワーカーは次の仕事を get() で待ち続けているため、cancel() で終了させる。キャンセルされたタスクは CancelledError で終わるため、gather(..., return_exceptions=True) で終了を待つ。

asyncio.Semaphore を使う方法と比べると、ワーカーの数だけタスクを作れば済むため、仕事の数が非常に多い場合でもタスクの数を抑えられる。

ブロッキングする処理との組み合わせ

第 8 章 asyncio による非同期処理（基礎） で説明したとおり、コルーチンの中でブロッキングする処理を呼ぶと、その間はイベントループ全体が止まる。次のサンプルでは、0.2 秒ごとに経過時間を表示するタスク（heartbeat()）と、1 秒かかるブロッキングする処理（blocking_io()）を並行に実行する。

blocking_call.py

 7import asyncio
 8import time
 9
10
11class Clock:
12    """開始からの経過時間を付けてメッセージを表示する。"""
13
14    def __init__(self) -> None:
15        self.start = time.perf_counter()
16
17    def log(self, message: str) -> None:
18        print(f"{time.perf_counter() - self.start:4.1f} 秒: {message}")
19
20
21def blocking_io() -> str:
22    """同期 API しか持たないライブラリの呼び出しを、time.sleep() で模擬する。"""
23    time.sleep(1.0)
24    return "同期処理の結果"
25
26
27async def heartbeat(clock: Clock) -> None:
28    for _ in range(6):
29        clock.log("heartbeat")
30        await asyncio.sleep(0.2)
31
32
33async def call_directly(clock: Clock) -> None:
34    clock.log("blocking_io() を直接呼ぶ")
35    clock.log(blocking_io())  # この 1 秒間、イベントループは止まる
36
37
38async def call_in_thread(clock: Clock) -> None:
39    clock.log("blocking_io() を asyncio.to_thread() で呼ぶ")
40    clock.log(await asyncio.to_thread(blocking_io))  # 別のスレッドで実行し、完了を await で待つ
41
42
43async def main() -> None:
44    print("--- 直接呼ぶ場合 ---")
45    clock = Clock()
46    await asyncio.gather(heartbeat(clock), call_directly(clock))
47
48    print("--- asyncio.to_thread() を使う場合 ---")
49    clock = Clock()
50    await asyncio.gather(heartbeat(clock), call_in_thread(clock))
51
52
53if __name__ == "__main__":
54    asyncio.run(main())

実行すると、次の結果になる。

--- 直接呼ぶ場合 ---
 0.0 秒: heartbeat
 0.0 秒: blocking_io() を直接呼ぶ
 1.0 秒: 同期処理の結果
 1.0 秒: heartbeat
 1.2 秒: heartbeat
 1.4 秒: heartbeat
 1.6 秒: heartbeat
 1.8 秒: heartbeat
--- asyncio.to_thread() を使う場合 ---
 0.0 秒: heartbeat
 0.0 秒: blocking_io() を asyncio.to_thread() で呼ぶ
 0.2 秒: heartbeat
 0.4 秒: heartbeat
 0.6 秒: heartbeat
 0.8 秒: heartbeat
 1.0 秒: 同期処理の結果
 1.0 秒: heartbeat

直接呼ぶ場合は、blocking_io() が実行されている 1 秒間、heartbeat() の表示が止まっている。asyncio.to_thread() を使う場合は、blocking_io() が別のスレッドで実行されるため、その間も heartbeat() が動き続けている。

ブロッキングする処理を asyncio から呼ぶ方法を次にまとめる。

表 18 ブロッキングする処理を asyncio から呼ぶ方法

方法

用途

await asyncio.to_thread(func, *args)

同期的な I/O を行う関数を、別のスレッドで実行する。同期的な API しか持たないライブラリを使う場合に使う。

await loop.run_in_executor(executor, func, *args)

指定した Executor で関数を実行する。ProcessPoolExecutor を指定すれば、CPU バウンドな処理を別のプロセスで実行できる（第 12 章 ケーススタディ で使う）。

loop は asyncio.get_running_loop() で取得する。asyncio.to_thread() も内部では既定の ThreadPoolExecutor を使っている。

コルーチンの中で次のような処理を呼んでいないか、注意が必要である。

  • time.sleep()（代わりに await asyncio.sleep() を使う）

  • requests や urllib.request などの同期的な HTTP クライアント

  • 同期的なデータベースのドライバー

  • 時間のかかる CPU バウンドな計算

  • 大きなファイルの読み書き

キャンセルと後始末

Task.cancel() を呼ぶと、そのタスクが await で中断している箇所に asyncio.CancelledError が送出される。asyncio.timeout() や TaskGroup も、内部でこの仕組みを使ってタスクをキャンセルしている。

タスクがキャンセルされても資源を確実に解放できるよう、後始末は try ... finally や async with で書く。

cancellation.py

 7import asyncio
 8
 9
10class Connection:
11    """後始末が必要な資源の例。"""
12
13    def __init__(self, name: str) -> None:
14        self.name = name
15        print(f"{name}: 接続を開いた")
16
17    def close(self) -> None:
18        print(f"{self.name}: 接続を閉じた")
19
20
21async def long_running(name: str) -> None:
22    connection = Connection(name)
23    try:
24        for step in range(1, 11):
25            await asyncio.sleep(0.3)
26            print(f"{name}: ステップ {step}")
27    finally:
28        connection.close()  # キャンセルされた場合も必ず実行される
29
30
31async def main() -> None:
32    task = asyncio.create_task(long_running("タスク"))
33    await asyncio.sleep(1.0)
34
35    task.cancel()
36    try:
37        await task
38    except asyncio.CancelledError:
39        print(f"キャンセルされた: cancelled() = {task.cancelled()}")
40
41
42if __name__ == "__main__":
43    asyncio.run(main())

実行すると、次の結果になる。

タスク: 接続を開いた
タスク: ステップ 1
タスク: ステップ 2
タスク: ステップ 3
タスク: 接続を閉じた
キャンセルされた: cancelled() = True

1 秒後に cancel() が呼ばれると、asyncio.sleep() で待っていたタスクに CancelledError が送出され、finally で接続が閉じられる。キャンセルについて、次の点に注意する。

  • CancelledError は Exception ではなく BaseException を継承している。そのため、except Exception: では捕まらない。

  • CancelledError を捕まえた場合は、後始末をした後に必ず送出し直す。握りつぶすと、キャンセルが正しく伝わらない。

  • await していない間（CPU バウンドな計算の最中など）は、キャンセルは届かない。次に await したときに初めて CancelledError が送出される。

よくある誤り

asyncio を使い始めたときに起こしやすい誤りを次にまとめる。

表 19 asyncio でよくある誤り

誤り

説明と対策

await を付け忘れる

コルーチン関数を await せずに呼ぶと、コルーチンが作られるだけで実行されない。RuntimeWarning: coroutine '...' was never awaited という警告が出る。mypy などの型チェッカーでも検出できる。

コルーチンの中でブロッキングする処理を呼ぶ

イベントループ全体が止まる。asyncio.to_thread() などで別のスレッドやプロセスに任せる。

作ったタスクの参照を保持しない

asyncio.create_task() の戻り値を保持しないと、タスクが途中で消えることがある。TaskGroup を使うか、戻り値を保持する。

タスクの例外を確認しない

create_task() で作ったタスクを待たずに放置すると、タスクの中で発生した例外に気付けない。TaskGroup を使えば、例外は必ず呼び出し元に伝わる。

タイムアウトを設定しない

相手が応答しないと、タスクが永久に待ち続ける。ネットワーク通信には asyncio.timeout() を設定する。

スレッドから asyncio のオブジェクトを直接操作する

asyncio のオブジェクトの多くはスレッドセーフではない。別のスレッドからイベントループに処理を依頼する場合は、asyncio.run_coroutine_threadsafe() や loop.call_soon_threadsafe() を使う。
