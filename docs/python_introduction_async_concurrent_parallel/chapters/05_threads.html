第 5 章 スレッドによる並行処理

この章では、threading モジュールを使ったスレッドによる並行処理を説明する。第 3 章 CPython の実行モデルと GIL で説明したとおり、通常の Python ではスレッドは I/O バウンドな処理に向いている。

スレッドの作成と実行

スレッドは threading.Thread クラスで作成する。target 引数にスレッドで実行する関数を、args 引数にその関数に渡す引数をタプルで指定する。

 1import threading
 2import time
 3
 4
 5def download(name: str) -> None:
 6    print(f"{name}: 開始")
 7    time.sleep(1.0)  # ダウンロードの代わり
 8    print(f"{name}: 終了")
 9
10
11threads = [threading.Thread(target=download, args=(f"file{i}",)) for i in range(3)]
12for thread in threads:
13    thread.start()  # スレッドの実行を開始する
14for thread in threads:
15    thread.join()  # スレッドが終了するまで待つ
16print("すべて終了")

start() メソッドでスレッドの実行が始まり、join() メソッドでスレッドの終了を待つ。3 つのスレッドはそれぞれ 1 秒待つが、待ち時間が重なるため、全体は約 1 秒で終わる。

スレッドで実行した関数の戻り値は、Thread クラスからは受け取れない。戻り値が必要な場合や、多数のタスクを扱う場合は、第 7 章 concurrent.futures による統一的な書き方 で説明する ThreadPoolExecutor を使うほうが簡単である。Thread クラスを直接使うのは、長時間動き続けるスレッドを作る場合など、スレッドの寿命を自分で管理したい場合である。

競合状態

スレッドは同じプロセスのメモリを共有するため、複数のスレッドから同じデータを読み書きできる。しかし、複数のスレッドが同じデータを同時に書き換えると、実行のタイミングによって結果が変わることがある。このような状態を 競合状態（race condition） という。

次のサンプルでは、4 つのスレッドがそれぞれ 1000 回ずつカウンターを 1 増やす。期待される結果は 4000 である。

race_condition.py

 7import threading
 8import time
 9from collections.abc import Callable
10
11THREADS = 4
12TIMES = 1000
13
14
15class Counter:
16    """複数のスレッドから更新されるカウンター。"""
17
18    def __init__(self) -> None:
19        self.value = 0
20        self._lock = threading.Lock()
21
22    def increment_unsafe(self) -> None:
23        current = self.value
24        time.sleep(0)  # 読み出しと書き込みの間で、他のスレッドに切り替わりやすくする
25        self.value = current + 1
26
27    def increment_safe(self) -> None:
28        with self._lock:
29            current = self.value
30            time.sleep(0)
31            self.value = current + 1
32
33
34def run(increment: Callable[[], None]) -> None:
35    """THREADS 個のスレッドで、それぞれ increment を TIMES 回呼び出す。"""
36
37    def worker() -> None:
38        for _ in range(TIMES):
39            increment()
40
41    threads = [threading.Thread(target=worker) for _ in range(THREADS)]
42    for thread in threads:
43        thread.start()
44    for thread in threads:
45        thread.join()
46
47
48def main() -> None:
49    expected = THREADS * TIMES
50
51    counter = Counter()
52    run(counter.increment_unsafe)
53    print(f"Lock なし: {counter.value} (期待値 {expected})")
54
55    counter = Counter()
56    run(counter.increment_safe)
57    print(f"Lock あり: {counter.value} (期待値 {expected})")
58
59
60if __name__ == "__main__":
61    main()

実行すると、次のような結果になる。

Lock なし: 1172 (期待値 4000)
Lock あり: 4000 (期待値 4000)

increment_unsafe() では、あるスレッドが値を読み出してから書き込むまでの間に、別のスレッドが同じ値を読み出して書き込むことがある。その結果、2 回分の増加が 1 回分しか反映されず、更新が失われる。このサンプルでは、問題を再現しやすくするため、読み出しと書き込みの間に time.sleep(0) を入れて、他のスレッドに切り替わりやすくしている。time.sleep(0) が無くても、切り替わるタイミングによっては同じ問題が起こる。発生の頻度が低いだけで、問題があることに変わりはない。

競合状態による不具合は、発生するかどうかが実行のタイミングに依存するため、テストで見つけにくく、再現も難しい。共有するデータを書き換える処理は、次に説明するロックで保護する必要がある。

ロックによる排他制御

threading.Lock は、ある範囲のコードを同時に 1 つのスレッドしか実行できないようにする仕組みである。このような制御を 排他制御 という。with 文で Lock を使うと、ブロックに入るときにロックを獲得し、ブロックを抜けるときに解放する。例外が発生した場合もロックは解放される。

上のサンプルの increment_safe() では、値の読み出しから書き込みまでを with self._lock: で囲んでいる。あるスレッドがこのブロックを実行している間、他のスレッドはブロックの入り口で待たされるため、更新が失われない。

ロックで保護する範囲は、必要な処理だけに絞る。ロックを持ったまま時間のかかる I/O を行うと、他のスレッドが待たされ、並行処理の利点が失われる。

threading モジュールには、Lock のほかにも次のような同期の仕組みがある。

表 8 threading モジュールの主な同期の仕組み

クラス

用途

Lock

同時に 1 つのスレッドだけが実行できる範囲を作る。

RLock

ロックを獲得したスレッドが、解放する前に同じロックをもう一度獲得できる Lock。ロックを獲得するメソッドから、同じロックを獲得する別のメソッドを呼ぶ場合に使う。

Semaphore

同時に実行できるスレッドの数を、指定した数までに制限する。接続先のサーバーへの同時接続数を制限する場合などに使う。

Event

あるスレッドから他のスレッドへ、「準備ができた」「停止せよ」などの合図を送る。

Condition

「キューにデータが入った」など、ある条件が満たされるまでスレッドを待たせる。

デッドロック

複数のロックを使う場合は、デッドロック に注意する必要がある。デッドロックとは、複数のスレッドが互いに相手の持つロックの解放を待ち、どのスレッドも先に進めなくなる状態である。

 1import threading
 2
 3lock_a = threading.Lock()
 4lock_b = threading.Lock()
 5
 6
 7def worker1() -> None:
 8    with lock_a:
 9        with lock_b:  # worker2 が lock_b を持っていると、ここで待ち続ける
10            print("worker1")
11
12
13def worker2() -> None:
14    with lock_b:
15        with lock_a:  # worker1 が lock_a を持っていると、ここで待ち続ける
16            print("worker2")

worker1() が lock_a を、worker2() が lock_b を獲得した時点で、両者は互いのロックの解放を待ち続ける。デッドロックを防ぐには、次の方法がある。

  • ロックを獲得する順序をすべてのスレッドで統一する。上の例では、worker2() も lock_a、lock_b の順に獲得すれば、デッドロックは起こらない。

  • ロックを持ったまま、別のロックを獲得する処理を呼ばない。ロックを 1 つしか使わない設計にできないかを検討する。

  • タイムアウトを設定する。lock.acquire(timeout=1.0) のように獲得の待ち時間に上限を設けると、少なくとも永久に止まることは防げる。

Queue による生産者・消費者パターン

ロックを正しく使い続けるのは難しい。スレッド間でデータを受け渡す場合は、共有データを直接書き換える代わりに、queue.Queue を使うとよい。Queue はスレッドから安全に使えるように作られており、内部で排他制御を行っている。

データを作るスレッド（生産者）が Queue にデータを入れ、データを処理するスレッド（消費者）が Queue から取り出す構成を、生産者・消費者パターン という。

producer_consumer.py

 8import queue
 9import threading
10import time
11
12CONSUMERS = 3
13JOBS = 10
14
15
16def producer(jobs: "queue.Queue[int | None]") -> None:
17    for number in range(JOBS):
18        jobs.put(number)  # キューが満杯のときは空きができるまで待つ
19        print(f"[生産者] 仕事 {number} を追加した")
20    for _ in range(CONSUMERS):
21        jobs.put(None)  # 番兵
22
23
24def consumer(jobs: "queue.Queue[int | None]", results: list[int], lock: threading.Lock) -> None:
25    name = threading.current_thread().name
26    while True:
27        number = jobs.get()  # キューが空のときは仕事が入るまで待つ
28        if number is None:
29            break
30        time.sleep(0.2)  # 時間のかかる I/O 処理の代わり
31        with lock:
32            results.append(number * number)
33        print(f"[{name}] 仕事 {number} を処理した")
34
35
36def main() -> None:
37    jobs: "queue.Queue[int | None]" = queue.Queue(maxsize=3)
38    results: list[int] = []
39    lock = threading.Lock()
40
41    consumers = [
42        threading.Thread(target=consumer, args=(jobs, results, lock), name=f"消費者 {i}")
43        for i in range(CONSUMERS)
44    ]
45    for thread in consumers:
46        thread.start()
47
48    start = time.perf_counter()
49    producer(jobs)
50    for thread in consumers:
51        thread.join()
52    elapsed = time.perf_counter() - start
53
54    print(f"結果: {sorted(results)}")
55    print(f"経過時間: {elapsed:.2f} 秒")
56
57
58if __name__ == "__main__":
59    main()

このサンプルのポイントは次のとおりである。

  • Queue(maxsize=3) のように上限を指定すると、キューが満杯のとき put() は空きができるまで待つ。生産が消費より速い場合でも、キューにデータがたまり続けてメモリを使い果たすことを防げる。

  • get() はキューが空のとき、データが入るまで待つ。消費者は、データが来るのを待つためのループやロックを自分で書く必要がない。

  • 仕事が無くなったことを伝えるため、消費者の数だけ番兵（None）を入れている。Python 3.13 以降では、Queue.shutdown() メソッドでキューを閉じる方法もある。

  • 結果のリスト results は複数のスレッドから書き換えるため、Lock で保護している。

デーモンスレッド

Python のプログラムは、通常、すべてのスレッドが終了するまで終了しない。Thread(target=..., daemon=True) のようにデーモンスレッドとして作成したスレッドは、デーモンでないスレッドがすべて終了した時点で、処理の途中であっても強制的に終了される。

デーモンスレッドは、終了時に後始末を行う機会が無いため、ファイルの書き込みなど途中で止まると困る処理には使わない。スレッドを確実に止めたい場合は、Event などで停止の合図を送り、スレッド自身にループを抜けさせる。

スレッドを使うときの指針

スレッドを使うときは、次の指針に従うと不具合を減らせる。

  • スレッド間で書き換え可能なデータを共有することは、できるだけ避ける。データの受け渡しには Queue を使う。

  • 共有が避けられない場合は、データとそれを保護するロックを 1 つのクラスにまとめ、クラスの外からはロックを意識せずに使えるようにする。

  • ライブラリのオブジェクトをスレッド間で共有する場合は、そのオブジェクトがスレッドセーフかどうかをドキュメントで確認する。たとえば標準ライブラリの sqlite3 の接続オブジェクトは、既定では作成したスレッド以外から使えない。

  • 戻り値や例外を受け取る必要がある場合は、Thread クラスを直接使わず、第 7 章 concurrent.futures による統一的な書き方 で説明する ThreadPoolExecutor を使う。
