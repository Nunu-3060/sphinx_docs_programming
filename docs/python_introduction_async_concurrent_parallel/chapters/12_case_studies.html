第 12 章 ケーススタディ

この章では、3 つの題材を通して、処理の性質から手法を選び、実装するまでの流れを確認する。いずれのサンプルも、標準ライブラリだけで、外部のネットワークを使わずに動作する。

多数の URL からのデータ取得

課題

Web API から 40 件のデータを取得したい。1 件ずつ取得すると、応答を待つ時間が積み重なって時間がかかる。ただし、相手のサーバーに負荷をかけないよう、同時に送る要求は 10 件までにしたい。また、応答が遅い要求があっても、全体が止まらないようにしたい。

手法の選択

処理時間の大半は応答を待つ時間であり、I/O バウンドである。同時に扱う要求の数は数十件程度なのでスレッドでも実現できるが、ここでは同時実行数の制限とタイムアウトを簡潔に書ける asyncio を選ぶ。

実装

サンプルでは、取得先の Web API の代わりに、同じプログラムの中で簡単な HTTP サーバーを起動する。サーバーは id によって応答までの時間を変え、10 件に 1 件は 2 秒かかる。クライアントは asyncio のストリームで HTTP の要求を送り、1 件ごとに 1 秒のタイムアウトを設定する。

fetch_many.py

 11import asyncio
 12import json
 13import time
 14from dataclasses import dataclass
 15
 16HOST = "127.0.0.1"
 17REQUESTS = 40
 18CONCURRENCY = 10
 19TIMEOUT_SECONDS = 1.0
 20
 21
 22# ---- サーバー側（取得先の Web API の代わり） ----
 23
 24def response_delay(item_id: int) -> float:
 25    """id ごとに応答までの時間を変える。10 件に 1 件は TIMEOUT_SECONDS より遅い。"""
 26    if item_id % 10 == 9:
 27        return 2.0
 28    return (item_id % 5) * 0.1
 29
 30
 31async def handle_http(reader: asyncio.StreamReader, writer: asyncio.StreamWriter) -> None:
 32    try:
 33        request_line = (await reader.readline()).decode()
 34        while (await reader.readline()) not in (b"\r\n", b""):
 35            pass  # ヘッダーは読み飛ばす
 36        path = request_line.split()[1]  # 例: "GET /items/3 HTTP/1.1"
 37        item_id = int(path.rsplit("/", 1)[1])
 38        await asyncio.sleep(response_delay(item_id))
 39        body = json.dumps({"id": item_id, "value": item_id * item_id}).encode()
 40        header = f"HTTP/1.1 200 OK\r\nContent-Type: application/json\r\nContent-Length: {len(body)}\r\n\r\n"
 41        writer.write(header.encode() + body)
 42        await writer.drain()
 43    except ConnectionError:
 44        pass  # クライアントがタイムアウトで切断した場合など
 45    finally:
 46        writer.close()
 47
 48
 49# ---- クライアント側 ----
 50
 51@dataclass
 52class Result:
 53    item_id: int
 54    value: int | None = None
 55    error: str | None = None
 56
 57
 58async def http_get_json(port: int, path: str) -> dict[str, int]:
 59    """HTTP/1.1 の GET リクエストを送り、JSON の本文を辞書として返す。"""
 60    reader, writer = await asyncio.open_connection(HOST, port)
 61    try:
 62        writer.write(f"GET {path} HTTP/1.1\r\nHost: {HOST}\r\nConnection: close\r\n\r\n".encode())
 63        await writer.drain()
 64        response = await reader.read()  # Connection: close なので、サーバーが閉じるまで読む
 65    finally:
 66        writer.close()
 67        await writer.wait_closed()
 68    _, body = response.split(b"\r\n\r\n", 1)
 69    data: dict[str, int] = json.loads(body)
 70    return data
 71
 72
 73async def fetch(item_id: int, port: int, semaphore: asyncio.Semaphore) -> Result:
 74    async with semaphore:
 75        try:
 76            async with asyncio.timeout(TIMEOUT_SECONDS):
 77                data = await http_get_json(port, f"/items/{item_id}")
 78        except TimeoutError:
 79            return Result(item_id, error="タイムアウト")
 80        except (ConnectionError, ValueError) as error:
 81            return Result(item_id, error=repr(error))
 82    return Result(item_id, value=data["value"])
 83
 84
 85async def main() -> None:
 86    server = await asyncio.start_server(handle_http, HOST, 0)
 87    port = server.sockets[0].getsockname()[1]
 88    async with server:
 89        semaphore = asyncio.Semaphore(CONCURRENCY)
 90        start = time.perf_counter()
 91        async with asyncio.TaskGroup() as group:
 92            tasks = [group.create_task(fetch(i, port, semaphore)) for i in range(REQUESTS)]
 93        elapsed = time.perf_counter() - start
 94
 95    results = [task.result() for task in tasks]
 96    succeeded = [r for r in results if r.error is None]
 97    failed = [r for r in results if r.error is not None]
 98    sequential = sum(min(response_delay(i), TIMEOUT_SECONDS) for i in range(REQUESTS))
 99
100    print(f"成功: {len(succeeded)} 件, 失敗: {len(failed)} 件")
101    for result in failed:
102        print(f"  id={result.item_id}: {result.error}")
103    print(f"経過時間: {elapsed:.1f} 秒（1 件ずつ取得した場合の待ち時間の合計: {sequential:.1f} 秒）")
104
105
106if __name__ == "__main__":
107    asyncio.run(main())

実行すると、次の結果になる。

成功: 36 件, 失敗: 4 件
  id=9: タイムアウト
  id=19: タイムアウト
  id=29: タイムアウト
  id=39: タイムアウト
経過時間: 1.8 秒（1 件ずつ取得した場合の待ち時間の合計: 10.4 秒）

要点

  • fetch() は、Semaphore で同時実行数を制限し、その中で asyncio.timeout() によって 1 件ごとの待ち時間を制限している。Semaphore の外側でタイムアウトを設定すると、順番を待っている時間もタイムアウトの対象になってしまうため、順序に注意する。

  • 失敗した要求は例外を送出せず、Result の error に記録している。TaskGroup の中で例外を送出すると他のタスクがすべてキャンセルされるため、一部の失敗を許容したい場合は、このようにタスクの中で例外を処理する。

  • 1 件ずつ取得すると待ち時間だけで 10 秒以上かかるところを、約 1.8 秒で取得できた。

実務では、HTTP の通信は aiohttp や httpx などのライブラリを使い、ステータスコードの確認や再試行（第 11 章 デバッグと性能計測 の retry() を参照）も加える。

大量のデータの一括処理

課題

マンデルブロ集合の画像（800 × 600 画素）を計算したい。画素ごとに複素数の計算を最大 200 回繰り返すため、Python で書くと時間がかかる。

手法の選択

処理時間の大半は Python で書かれた計算であり、CPU バウンドである。各行の計算は他の行に依存しないため、行ごとに分けて並列に計算できる。ProcessPoolExecutor を選ぶ。

実装

mandelbrot_batch.py

 7import os
 8import time
 9from concurrent.futures import ProcessPoolExecutor
10from pathlib import Path
11
12WIDTH = 800
13HEIGHT = 600
14MAX_ITERATIONS = 200
15
16
17def compute_row(y: int) -> bytes:
18    """y 行目の各画素について、発散するまでの反復回数を明るさ（0〜255）に変換して返す。"""
19    imaginary = (y / HEIGHT) * 2.4 - 1.2
20    row = bytearray(WIDTH)
21    for x in range(WIDTH):
22        c = complex((x / WIDTH) * 3.2 - 2.2, imaginary)
23        z = 0j
24        iterations = 0
25        while abs(z) <= 2.0 and iterations < MAX_ITERATIONS:
26            z = z * z + c
27            iterations += 1
28        row[x] = 255 - iterations * 255 // MAX_ITERATIONS
29    return bytes(row)
30
31
32def save_pgm(path: Path, rows: list[bytes]) -> None:
33    header = f"P5\n{WIDTH} {HEIGHT}\n255\n".encode("ascii")
34    path.write_bytes(header + b"".join(rows))
35
36
37def main() -> None:
38    start = time.perf_counter()
39    rows = [compute_row(y) for y in range(HEIGHT)]
40    print(f"逐次: {time.perf_counter() - start:.2f} 秒")
41
42    start = time.perf_counter()
43    with ProcessPoolExecutor() as executor:
44        # 1 行ずつ送ると受け渡しの回数が増えるため、chunksize でまとめて送る
45        chunksize = max(1, HEIGHT // ((os.cpu_count() or 1) * 4))
46        parallel_rows = list(executor.map(compute_row, range(HEIGHT), chunksize=chunksize))
47    print(f"プロセス: {time.perf_counter() - start:.2f} 秒 (chunksize={chunksize})")
48
49    assert parallel_rows == rows
50    output = Path("mandelbrot.pgm")
51    save_pgm(output, parallel_rows)
52    print(f"{output.resolve()} に保存した")
53
54
55if __name__ == "__main__":
56    main()

実行すると、次のような結果になり、実行したディレクトリに mandelbrot.pgm が保存される。PGM は白黒の画像形式であり、GIMP などの画像編集ソフトで表示できる。

逐次: 5.44 秒
プロセス: 1.38 秒 (chunksize=9)

要点

  • compute_row() は 1 行分の計算をする関数で、引数は行番号、戻り値は 800 バイトの bytes である。受け渡すデータが小さいため、プロセス間の受け渡しの負荷が小さい。

  • chunksize は、コア数の 4 倍程度の塊に分かれるように計算している。塊が大きすぎると、計算量の多い行（集合の内部の行）が特定のプロセスに偏り、早く終わったプロセスが遊んでしまう。塊が小さすぎると、受け渡しの回数が増える。

  • 逐次処理の結果と並列処理の結果が一致することを assert で確認している。並列化したときは、結果が変わっていないことを必ず確認する。

I/O と CPU の処理が混在するパイプライン

課題

12 件のデータをネットワークから取得し、それぞれを解析したい。取得には 1 件あたり 0.3 秒の待ち時間があり、解析は CPU バウンドな計算である。

手法の選択

取得は I/O バウンド、解析は CPU バウンドである。1 つの手法では両方を効率よく処理できないため、取得には asyncio を、解析にはプロセスを使い、loop.run_in_executor() で組み合わせる。

実装

pipeline.py

 8import asyncio
 9import hashlib
10import time
11from concurrent.futures import ProcessPoolExecutor
12
13ITEMS = 12
14CONCURRENCY = 4
15
16
17async def download(item_id: int) -> bytes:
18    """データの取得を模擬する（0.3 秒かかる I/O）。"""
19    await asyncio.sleep(0.3)
20    return f"data-{item_id}".encode() * 1000
21
22
23def analyze(data: bytes) -> str:
24    """データの解析を模擬する（CPU バウンド）。ハッシュ値を繰り返し計算する。"""
25    digest = data
26    for _ in range(200_000):
27        digest = hashlib.sha256(digest).digest()
28    return digest.hex()[:12]
29
30
31async def process_blocking(item_id: int, semaphore: asyncio.Semaphore) -> str:
32    """解析をイベントループの中で直接実行する（悪い例）。解析中は他のタスクがすべて止まる。"""
33    async with semaphore:
34        data = await download(item_id)
35    return analyze(data)
36
37
38async def process_offloaded(item_id: int, semaphore: asyncio.Semaphore, executor: ProcessPoolExecutor) -> str:
39    """解析をプロセスプールで実行する。解析中も他のタスクの取得は進む。"""
40    async with semaphore:
41        data = await download(item_id)
42    loop = asyncio.get_running_loop()
43    return await loop.run_in_executor(executor, analyze, data)
44
45
46async def main() -> None:
47    semaphore = asyncio.Semaphore(CONCURRENCY)
48
49    start = time.perf_counter()
50    async with asyncio.TaskGroup() as group:
51        for i in range(ITEMS):
52            group.create_task(process_blocking(i, semaphore))
53    print(f"イベントループの中で解析: {time.perf_counter() - start:.2f} 秒")
54
55    with ProcessPoolExecutor() as executor:
56        executor.submit(int).result()  # プロセスの起動を計測から除くため、先に一度使っておく
57        start = time.perf_counter()
58        async with asyncio.TaskGroup() as group:
59            tasks = [group.create_task(process_offloaded(i, semaphore, executor)) for i in range(ITEMS)]
60        print(f"プロセスプールで解析: {time.perf_counter() - start:.2f} 秒")
61
62    print(f"解析結果の例: {tasks[0].result()}")
63
64
65if __name__ == "__main__":
66    asyncio.run(main())

執筆環境では次の結果になった。

イベントループの中で解析: 3.79 秒
プロセスプールで解析: 1.36 秒
解析結果の例: 6ea8810e6841

要点

  • process_blocking() は、解析をイベントループの中で直接実行する悪い例である。解析の間はイベントループが止まるため、他のタスクの取得も進まない。

  • process_offloaded() は、loop.run_in_executor() で解析をプロセスプールに任せる。解析の結果を await で待つ間もイベントループは動き続けるため、他のタスクの取得が進み、さらに複数の解析が並列に実行される。

  • analyze() で使っている hashlib.sha256() は、大きなデータを処理する間は GIL を解放するが、このサンプルのように 32 バイトの小さなデータを繰り返し処理する場合はほとんど解放しない。そのため、スレッド（asyncio.to_thread()）ではなくプロセスを使っている。

  • ProcessPoolExecutor は asyncio.run() の中で作成し、with 文で確実に終了させている。

このように、1 つのプログラムの中でも、処理の部分ごとに性質を見極めて手法を使い分けることが重要である。
