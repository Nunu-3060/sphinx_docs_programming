第 6 章 プロセスによる並列処理

この章では、プロセスを使った並列処理を説明する。プロセスはそれぞれが独立した Python のインタプリタと GIL を持つため、Python で書かれた CPU バウンドな処理を複数の CPU コアで並列に実行できる。

ProcessPoolExecutor による並列処理

プロセスを使う方法には、multiprocessing モジュールと concurrent.futures モジュールの ProcessPoolExecutor がある。多くの場合は、使い方が簡単な ProcessPoolExecutor を使えばよい。

ProcessPoolExecutor は、あらかじめ決まった数のプロセス（ワーカープロセス）を起動しておき、渡されたタスクを空いているプロセスに割り当てて実行する。このように、作成済みの実行単位を再利用する仕組みを プール という。ワーカープロセスの数を省略すると、CPU のコア数と同じ数のプロセスが起動される。

次のサンプルでは、200 万未満の素数の個数を数える処理を 16 個の範囲に分割し、プロセスに分けて並列に数える。

prime_pool.py

 7import math
 8import multiprocessing
 9import os
10import time
11from concurrent.futures import ProcessPoolExecutor
12
13LIMIT = 2_000_000
14CHUNKS = 16
15
16
17def is_prime(n: int) -> bool:
18    if n < 2:
19        return False
20    if n % 2 == 0:
21        return n == 2
22    for divisor in range(3, math.isqrt(n) + 1, 2):
23        if n % divisor == 0:
24            return False
25    return True
26
27
28def count_primes(start: int, stop: int) -> int:
29    """start 以上 stop 未満の素数の個数を返す。"""
30    return sum(1 for n in range(start, stop) if is_prime(n))
31
32
33def split_range(limit: int, chunks: int) -> list[tuple[int, int]]:
34    """0 以上 limit 未満の範囲を chunks 個に分割する。"""
35    size = math.ceil(limit / chunks)
36    return [(start, min(start + size, limit)) for start in range(0, limit, size)]
37
38
39def main() -> None:
40    print(f"起動方式: {multiprocessing.get_start_method()}, CPU コア数: {os.cpu_count()}")
41    ranges = split_range(LIMIT, CHUNKS)
42
43    start = time.perf_counter()
44    total = sum(count_primes(a, b) for a, b in ranges)
45    print(f"逐次: {total} 個, {time.perf_counter() - start:.2f} 秒")
46
47    start = time.perf_counter()
48    with ProcessPoolExecutor() as executor:
49        starts = [a for a, _ in ranges]
50        stops = [b for _, b in ranges]
51        total = sum(executor.map(count_primes, starts, stops))
52    print(f"プロセス: {total} 個, {time.perf_counter() - start:.2f} 秒")
53
54
55# spawn 方式では子プロセスがこのファイルを import するため、この判定が必要になる。
56if __name__ == "__main__":
57    main()

執筆環境では次の結果になった。

起動方式: spawn, CPU コア数: 16
逐次: 148933 個, 5.84 秒
プロセス: 148933 個, 1.53 秒

executor.map(count_primes, starts, stops) は、組み込みの map() 関数と同じように、starts と stops から 1 つずつ取り出した値を引数として count_primes() を呼び出し、その結果を順に返す。各呼び出しは別のプロセスで並列に実行される。

16 コアで約 3.8 倍の速さにとどまっているのは、プロセスの起動に時間がかかることと、範囲によって素数の判定にかかる時間が異なり、早く終わったプロセスが遊んでしまうことが主な理由である。

起動方式と if __name__ == "__main__"

multiprocessing は、子プロセスを起動する方式として次の 3 つを持っている。

表 10 プロセスの起動方式

方式

説明

既定になっている OS

spawn

新しい Python のインタプリタを起動し、親プロセスのメインモジュールを import してから、指定された関数を実行する。起動は遅いが安全である。

Windows、macOS

fork

OS の fork によって、親プロセスのメモリをそのまま複製する。起動は速いが、親プロセスがスレッドを使っている場合に、ロックの状態が不整合になってデッドロックするおそれがある。

Python 3.13 以前の Linux

forkserver

最初に 1 つのサーバープロセスを起動しておき、以降の子プロセスはそのサーバープロセスから fork して作る。fork の速さを生かしつつ、fork の問題を避ける。

Python 3.14 以降の Linux など（macOS を除く POSIX 系 OS）

spawn 方式と forkserver 方式では、子プロセスが親プロセスのメインモジュール（実行したファイル）を import する。そのため、プロセスを起動するコードを if __name__ == "__main__": の中に書かないと、子プロセスが import したときにも同じコードが実行され、子プロセスがさらにプロセスを起動しようとしてエラーになる。プロセスを使うプログラムでは、必ずこの判定を書く。

起動方式は、multiprocessing.get_context("spawn") のように明示的に指定することもできる。OS によって動作が変わることを避けたい場合は、起動方式を明示するとよい。

pickle によるデータの受け渡し

プロセスはメモリを共有しないため、関数や引数、戻り値は pickle モジュールでバイト列に変換（シリアライズ）してプロセス間で送られる。そのため、プロセスに渡すものには次の制約がある。

  • 関数はモジュールの最上位で定義する。ラムダ式や、関数の中で定義した関数は pickle できないため、プロセスに渡せない。

  • 引数と戻り値は pickle できるものにする。開いたファイル、ソケット、ロック、データベースの接続などは pickle できない。

  • 大きなデータの受け渡しには時間がかかる。引数と戻り値は毎回コピーされるため、大きなデータを何度も送ると、受け渡しの時間が計算の時間を上回ることがある。

たとえば、次のコードは PicklingError などのエラーになる。

1from concurrent.futures import ProcessPoolExecutor
2
3if __name__ == "__main__":
4    with ProcessPoolExecutor() as executor:
5        # ラムダ式は pickle できないため、プロセスに渡せない
6        results = list(executor.map(lambda x: x * x, range(10)))

プロセスの起動とデータの受け渡しの負荷

プロセスを使った並列処理では、次の時間が余分にかかる。

  • プロセスを起動する時間（spawn 方式では 1 プロセスあたり数十から数百ミリ秒）

  • 引数と戻り値を pickle し、プロセス間で送受信する時間

1 回あたりの処理が小さい場合、この余分な時間が処理そのものの時間を上回り、逐次処理より遅くなる。ProcessPoolExecutor.map() の chunksize 引数を指定すると、複数の要素をまとめて 1 回で送るため、受け渡しの回数を減らせる。

chunksize.py

 7import time
 8from concurrent.futures import ProcessPoolExecutor
 9
10ITEMS = 10_000
11
12
13def square(n: int) -> int:
14    return n * n
15
16
17def main() -> None:
18    numbers = range(ITEMS)
19
20    start = time.perf_counter()
21    expected = [square(n) for n in numbers]
22    print(f"逐次: {time.perf_counter() - start:.2f} 秒")
23
24    with ProcessPoolExecutor(max_workers=4) as executor:
25        list(executor.map(square, range(10)))  # プロセスの起動を計測から除くため、先に一度使っておく
26        for chunksize in (1, 100, 1000):
27            start = time.perf_counter()
28            results = list(executor.map(square, numbers, chunksize=chunksize))
29            elapsed = time.perf_counter() - start
30            assert results == expected
31            print(f"プロセス (chunksize={chunksize}): {elapsed:.2f} 秒")
32
33
34if __name__ == "__main__":
35    main()

執筆環境では次の結果になった。

逐次: 0.00 秒
プロセス (chunksize=1): 3.15 秒
プロセス (chunksize=100): 0.05 秒
プロセス (chunksize=1000): 0.02 秒

square() のように一瞬で終わる処理では、どの chunksize でも逐次処理より遅い。chunksize=1（既定値）では、1 万回の受け渡しに 3 秒以上かかっている。プロセスに渡すタスクは、1 回あたりの処理時間が受け渡しの時間より十分に大きくなるようにまとめる必要がある。prime_pool.py で範囲を 16 個に分割して渡しているのも、このためである。

共有メモリ

大きなデータを複数のプロセスで読む場合は、データを毎回コピーする代わりに、multiprocessing.shared_memory モジュールの共有メモリを使う方法がある。共有メモリは、複数のプロセスから同じメモリ領域を読み書きできる仕組みである。

次のサンプルでは、親プロセスが共有メモリに 100 万個の浮動小数点数を書き込み、4 つの子プロセスが担当する範囲の和を計算する。子プロセスに送るのは、共有メモリの名前と範囲だけである。

shared_memory_sum.py

 7import struct
 8from concurrent.futures import ProcessPoolExecutor
 9from multiprocessing import shared_memory
10
11COUNT = 1_000_000
12WORKERS = 4
13ITEM_SIZE = struct.calcsize("d")  # double（8 バイト）
14
15
16def as_doubles(memory: shared_memory.SharedMemory) -> "memoryview[float]":
17    """共有メモリを double の配列として読み書きできる memoryview を返す。"""
18    if memory.buf is None:
19        raise ValueError("共有メモリは既に閉じられている")
20    return memory.buf.cast("d")
21
22
23def partial_sum(name: str, start: int, stop: int) -> float:
24    """共有メモリ name に置かれた配列の start 番目から stop - 1 番目までの和を返す。"""
25    memory = shared_memory.SharedMemory(name=name)
26    try:
27        values = as_doubles(memory)
28        try:
29            return sum(values[start:stop])
30        finally:
31            values.release()  # memoryview を解放してから close する
32    finally:
33        memory.close()
34
35
36def main() -> None:
37    memory = shared_memory.SharedMemory(create=True, size=COUNT * ITEM_SIZE)
38    try:
39        values = as_doubles(memory)
40        for i in range(COUNT):
41            values[i] = i * 0.5
42        values.release()
43
44        size = COUNT // WORKERS
45        starts = [i * size for i in range(WORKERS)]
46        stops = [start + size for start in starts]
47        stops[-1] = COUNT
48        with ProcessPoolExecutor(max_workers=WORKERS) as executor:
49            sums = list(executor.map(partial_sum, [memory.name] * WORKERS, starts, stops))
50
51        print(f"部分和: {sums}")
52        print(f"合計: {sum(sums)} (期待値 {sum(i * 0.5 for i in range(COUNT))})")
53    finally:
54        memory.close()
55        memory.unlink()  # 共有メモリを作ったプロセスが最後に削除する
56
57
58if __name__ == "__main__":
59    main()

共有メモリを使うときは、次の点に注意する。

  • 共有メモリはバイト列として扱われるため、memoryview.cast() などでデータの型を指定して読み書きする。NumPy を使える環境では、共有メモリの上に NumPy の配列を作ることもできる。

  • 複数のプロセスが同じ範囲を書き換える場合は、排他制御が必要になる。このサンプルでは、子プロセスは読むだけなので排他制御は不要である。

  • 使い終わった共有メモリは、各プロセスで close() し、作成したプロセスが最後に unlink() して削除する。

プロセス間でデータをやり取りする方法には、このほかに multiprocessing.Queue や multiprocessing.Pipe もある。
